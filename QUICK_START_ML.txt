```bash

node script/mlCalibrationFramework.mjs
# Look for red flags in factors

# Rollback immediately
# Use old model snapshot from backups/
# Report issue for investigation
```

### Symptom: Calibration dial falls below 60
```bash
# This means retrain failed somehow
# Stop production use of model
# Investigate: features might be corrupt
# Rollback to previous working version
```

### Symptom: Win rate goes down but dial stays high
```bash
# Could be market shift, not model issue
# Check: Are win/loss outcomes being logged correctly?
# Verify: Training data timestamp is recent
# Solution: Manually trigger retrain with latest data
```

- **Solution:** Replace weak signals with strong context

### Smart Weighting
- **Problem:** Model learns "how to win" not "how to avoid losing"
- **Solution:** Penalize mistakes more than reward wins
- **Result:** More careful, profitable trades

## 🎓 Understanding the Metrics

### Calibration Dial
- Higher = model more trustworthy
- 85+: Use with confidence
- 70-85: Good enough, monitor
- <70: Needs retraining

### Feature Importance  
- Shows which inputs drive decisions
- Top 3 should account for 50%+
- If top features drop: model degrading
- If all features similar: model confused

### Outcome Weights
- Tells model: "This outcome matters 2.5x more"
- Missses = high cost (player fails to execute)
- Losses = medium cost (executed, lost money)
- Wins = baseline cost (good prediction)
