# 10-Minute Signal Logging System

## Overview
A complete 10-minute interval signal logging and monitoring system has been implemented to help you tune the engine better. Every 10 minutes, the system automatically collects all signals generated by the scanner and records them with detailed metrics.

## System Architecture

### Backend Components

#### 1. **Engine Intake Log** (`server/engineIntakeLog.ts`)
- **Purpose**: Core 10-minute interval collection system
- **Cadence**: Rolls every 10 minutes at boundary intervals
- **Data Collected**:
  - Total symbols scanned
  - Signals created (count & breakdown by type/direction)
  - Average scores (breakout, edge, confidence)
  - Per-signal details with triggers and indicators
  - Top triggers ranked by frequency & effectiveness
  - Engine state aggregates
  - Quality metrics (readiness score, health grade)

#### 2. **Engine Intake Scheduler** (`server/engineIntakeScheduler.ts`)
- **Auto-starts** on server startup (5 seconds delay)
- **Manages** 10-minute interval timing
- **Handles** collection rolls and persistence
- Currently running: ✅ (imported and called in `server/index.ts`)

#### 3. **Scanner Integration** (`server/scannerIntegration.ts`)
- **Hooks into** scanner signal generation
- **Records** each signal to current interval buffer
- **Extracts**: triggers, reasons, indicators
- **Filters**: Only records signals with actual breakout or edgeScore > 30

#### 4. **Signal Recording**
- When scanner generates a signal → `recordScannerSignal()` is called
- Signal metadata is extracted and stored in memory buffer
- Every 10 minutes → buffer is rolled into log file
- Log stored in: `logs/engine_intake_*.jsonl`

### Frontend Components

#### 5. **Signal Logging Panel** (`client/src/components/SignalLoggingPanel.tsx`)
- **Real-time display** of 10-minute intake logs
- **Two view modes**:
  - **Latest**: Shows most recent 10-minute snapshot
  - **Recent**: Shows last 12 intervals (2 hours)
  
- **Displays**:
  - Summary stats: symbols scanned, signals created, avg scores
  - Signal breakdown by type (BREAKOUT, BREAKDOWN, SQUEEZE, etc.)
  - Signal breakdown by direction (bullish/bearish/neutral)
  - Top triggers causing signals
  - Quality metrics (health grade, market condition, readiness score)
  - Per-symbol statistics
  - Engine state aggregates

#### 6. **Dashboard Integration**
- Added to Dashboard sidebar (right column)
- Positioned between MLCalibrationGauge and EdgeTuningCard
- Auto-refreshes every 60 seconds
- Accessible on any ticker view

### API Endpoints

#### GET `/api/intake/latest`
Returns the most recent 10-minute intake entry
```json
{
  "success": true,
  "latest": { EngineIntakeEntry },
  "timestamp": 1234567890
}
```

#### GET `/api/intake/recent?limit=12`
Returns recent intake entries (default 10, max 100)
```json
{
  "success": true,
  "entries": [ EngineIntakeEntry[] ],
  "count": 12,
  "timestamp": 1234567890
}
```

## Data Structure

### EngineIntakeEntry
```typescript
{
  timestamp: ISO string,           // "2026-05-03T15:30:00Z"
  unixMs: number,                  // Unix milliseconds
  intervalMinutes: number,         // Usually 10
  isMarketOpen: boolean,
  
  summary: {
    totalSymbolsScanned: number,
    signalsCreated: number,
    signalsByType: { [type]: count },       // BREAKOUT: 5, SQUEEZE: 2, etc.
    signalsByDirection: { [dir]: count },   // bullish: 3, bearish: 2, neutral: 2
    avgBreakoutScore: number,
    avgEdgeScore: number,
    avgConfidence: number,
  },
  
  signals: SignalSnapshot[],    // Detailed per-signal data
  
  bySymbol: {                   // Per-symbol statistics
    [symbol]: {
      scanned: boolean,
      signalsCreated: number,
      signalTypes: string[],
      highestScore: number,
      avgConfidence: number,
    }
  },
  
  topTriggers: [
    {
      reason: string,           // e.g., "compression: squeeze", "rsi_overbought"
      frequency: number,        // How many times triggered
      avgScore: number,         // Average edge score when triggered
    }
  ],
  
  quality: {
    readinessScore: number,     // 0-100: how ready engine is to signal
    healthScore: 'A' | 'B' | 'C' | 'D' | 'F',
    volatilityRegime: string,
    marketCondition: string,
  }
}
```

## How to Use for Engine Tuning

### 1. **Identify Trigger Patterns**
- Look at `topTriggers` to see what's causing most signals
- Check `avgScore` of each trigger to see which are most effective
- Focus tuning on high-frequency but low-scoring triggers

### 2. **Monitor Signal Quality**
- Track `healthScore` over time
- Watch `readinessScore` - if consistently low, engine may need calibration
- Check `signalsByDirection` balance - too many one-sided signals?

### 3. **Per-Symbol Analysis**
- Use `bySymbol` data to identify which symbols generate best signals
- Find symbols with high `avgConfidence` scores
- Identify symbols where you consistently see good setups

### 4. **Signal Type Distribution**
- Monitor `signalsByType` to ensure healthy mix
- If one type dominates, verify it's not over-tuned
- Compare win rates across different signal types

### 5. **Confidence Calibration**
- Compare `avgConfidence` across time intervals
- If confidence drops during market open, may need to adjust for volatility
- Track correlation between confidence and actual win rates

## Troubleshooting

### Logs Not Updating?
1. Check backend is running: `console.log` for "[EngineIntakeScheduler]"
2. Verify scanner is actively processing: signals must exist to log
3. Check market hours - less data outside trading hours

### No Signals Appearing?
1. Scanner must generate signals (breakout events)
2. Edge score must be > 30 for recording
3. Check symbols are being scanned

### Timestamps Off?
1. Verify system time is correct
2. 10-minute rolls happen at boundaries (0, 10, 20, 30, etc. minute marks)
3. First log entry appears 10 minutes after startup
